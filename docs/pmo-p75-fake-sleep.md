# PMO P75「假休眠」现象记录（2026-10-19 实测）

> **结论：固件 bug。刷 2026-10-24 的接收器+键盘双固件后仍未修复，已整理成报告给厂商。**
> 本文保留完整取证过程——以后遇到「接收器说连着但键盘不应答」可以直接对照。
>
> 刷机后复测（关键）：**关灯依旧假休眠**，`state=05` 连续 3 分钟无恢复，
> `deepSleepTime` 仍是 `1 分钟`。已整理成可直接发给客服的报告：
> [`pmo-p75-bug-report.md`](pmo-p75-bug-report.md)
>
> 刷机前后版本：RDR `deviceInfo` 的 firmwareVer 从 `0x0116` → `0x0113`（1.19）。

## 现象

关灯后键盘极快进入一种**不能自主恢复的假休眠**：

- 接收器仍然报「已配对、已连接」，主机/驱动以为一切正常
- 键盘本体完全不响应任何 RDR 配置命令（连 `0x10` 握手都无回应）
- 按物理按键没反应（键盘其实没在收）
- **不会自己醒**，必须切到蓝牙再切回 2.4G（等效重连）才恢复
- 官方驱动 PMOHub 同样复现

## 实测数据

### 1. 休眠配置（醒着时读 funcInfo，`0x14`，需先 `0x10` 握手）

```
灯光开关  0        ← 关灯状态下读回 0
灯效/亮度 5 / 27
休眠时间  255 分钟  ← FF FF 开头 = 固件「未设置」标记
深度休眠  1 分钟   ← ★ 关键
```

原始 41 字节：
```
00 00 05 1B 03 00 06 00 FF FF 06 01 01 21 03 01 00 FF FF FF
00 01 5A 03 01 00 FF 00 00 01 02 0A 03 01 00 FF 00 00 01 00 00
```

### 2. 接收器状态帧（`0xD0`，走 0xFF60，32 字节）

醒着：
```
00 AA D0 00 00 18 00 00 00 01 B0 36 2B 30 04 00
                                      ↑vid  ↑pid  ↑state=04
```

假休眠：
```
00 AA D0 00 00 18 00 00 00 01 B0 36 2B 30 05 00
                                              ↑state=05
```

`state` 字节：**04 = 正常 / 05 = 假休眠**。这个字节是目前唯一能从主机侧区分两种状态的信号。

### 3. 时间线（关灯后，20 秒一轮）

```
20:56:06  state=05  电量 —   握手无回应
20:56:27  state=05  电量 —   握手无回应
20:56:48  state=05  电量 —   握手无回应
20:57:09  state=05  电量 —   握手无回应
20:57:30  state=05  电量 —   握手无回应
20:57:51  state=05  电量 —   握手无回应
20:58:12  state=05  电量 —   握手无回应
20:58:33  state=05  电量 —   握手无回应
20:58:54  state=05  电量 —   握手无回应
```

持续 3 分钟以上没有任何恢复迹象。

### 4. 尝试软件唤醒（8 种帧，全部无效）

| 尝试 | 结果 |
|---|---|
| `0xD0` 状态轮询 | 仍无回应 |
| `0x10` 连发 5 次 | 仍无回应 |
| `0x12` 设备信息 | 仍无回应 |
| `0x14` funcInfo | 仍无回应 |
| `0x30` 电池 | 仍无回应 |
| `0x10` + `0x30` 组合 | 仍无回应 |
| 全零帧 | 仍无回应 |
| `0xAA` 单字节 | 仍无回应 |

**结论：主机侧无法唤醒，只能物理重连。**

## 判断

固件在「关灯 → 低功耗」这条路径上的状态机有缺陷：

1. 关灯后进入的省电模式门槛过低（`deepSleepTime = 1 分钟`）
2. 进入深度休眠时没有正确通知接收器断链（所以接收器还认为连着）
3. 进入后 USB/2.4G 配置通道彻底停摆，且没有唤醒源

驱动同样复现 → 不是驱动问题，也不是主机侧协议问题，是键盘固件问题。

## 解决

2026-10-24 向 PMO 客服申请到两个固件（`P75接收器固件.exe` + `P75键盘固件.exe`）并均刷写。

**刷完关灯复测：问题依旧。**

```
接收器: 00 AA D0 00 00 18 00 00 00 01 B0 36 2B 30 05 00   ← state=05 假休眠
键盘:   0x10 握手无回应
深度休眠: 1 分钟（门槛没变）
```

回归脚本 `tools/regress_sleep.py` 连续 3 分钟全部判为「假休眠复发」。
接收器侧候选重连指令（`0xD1/0xD2/0xB4`–`0xBF`）也全部无效。

→ 已整理成正式报告：[`pmo-p75-bug-report.md`](pmo-p75-bug-report.md)

## 给固件厂商的报告要点（历史记录）

1. `funcInfo` 里 `deepSleepTime` 在关灯状态下是 **1 分钟**
2. 深度休眠时应通过接收器上报断开（`0xD0` 的 `state` 字节应能区分，而不是继续报 `04/05` 混淆）
3. 深度休眠应保留至少一个唤醒源（当时连 `0x10` 都不响应）

## 复现 / 取证脚本

```bash
python tools\pmo_diag.py          # 一次性：状态帧 + 电量 + 灯光/休眠配置
python tools\watch_sleep.py 2000  # 后台长跑：每 20 秒记录一次
python tools\try_wake.py          # 假休眠时试 8 种唤醒帧
python tools\try_reconnect.py     # 假休眠时试接收器侧重连指令
python tools\regress_sleep.py 5   # 刷固件后的回归验证
python tools\pmo_version.py       # 读 RDR 固件版本号
```

## 缓解（固件真正修好之前）

- 别让它在关灯状态下闲置超过 1 分钟，或保持开灯
- 出问题后切蓝牙再切回来（最可靠）
- 插一下 USB 线通常也能踢醒（比切蓝牙快）
- 用本工具：`python tools\watch_sleep.py` 能第一时间看出它掉没掉（`state` 04→05）
