# PMO P75 关灯后「假休眠」问题报告（刷固件后仍未修复）

提交给：PMO 技术支持
设备：PMO P75 键盘 + RDR 2.4G 接收器
固件：`P75接收器固件.exe` + `P75键盘固件.exe`（2026-10-24，均已刷写）
键盘 RDR 版本读数：`0x0113`（1.19）
日期：2026-10-19 首次复现 / 2026-10-24 刷固件后复测

---

## 一句话结论

**刷了 10-24 的两个固件后，关灯依旧会进入假休眠，问题没有修复。**

---

## 现象

1. 键盘**关闭全部灯光**后，约 1 分钟内进入一种异常休眠
2. 此时 **2.4G 接收器仍然上报「已配对、已连接」**（状态字节 `state=05`）
3. 键盘本体**完全不响应任何 2.4G 配置命令**，包括最基本的握手命令 `0x10`
4. **按物理按键无任何反应**（键盘并未在接收数据）
5. **不会自主恢复**，必须切到蓝牙再切回 2.4G（等效重连）才恢复
6. 官方驱动 PMOHub 同样复现

---

## 实测证据

### 1. 接收器状态帧（`0xD0` 轮询，走 usage page `0xFF60`，32 字节帧）

**正常时：**
```
00 AA D0 00 00 18 00 00 00 01 B0 36 2B 30 04 00
                                      ↑vid  ↑pid  ↑state=04
```

**假休眠时：**
```
00 AA D0 00 00 18 00 00 00 01 B0 36 2B 30 05 00
                                              ↑state=05
```

`state` 字节是唯一能从主机侧区分两种状态的信号：**04 = 正常，05 = 假休眠**。

### 2. 假休眠时间线（20 秒采样一次，连续 3 分钟无任何恢复）

### 3. 键盘休眠配置（醒着时通过 `0x14` funcInfo 读出，需先 `0x10` 握手）

```
灯光开关  1（开）/ 0（关）
灯效/亮度 1 / 60
休眠时间  255 分钟（原始字节 FF FF，固件「未设置」标记）
深度休眠  1 分钟   ← 关键
```

原始 41 字节（开灯状态）：
```
00 01 01 3C 03 01 00 FF 00 00 00 01 01 3C 03 01 00 FF 00 00
00 01 5A 03 01 00 FF 00 00 01 00 0A 03 01 00 FF 00 00 01 00 00
```

刷固件前后 `deepSleepTime` **都还是 1 分钟**，门槛没有变化。

### 4. 主机侧唤醒尝试（全部失败）

假休眠期间，从主机向接收器发送以下帧，键盘均无任何响应：

| 尝试 | 结果 |
|---|---|
| `0xD0` 状态轮询 | 无回应 |
| `0x10` 握手（连发 5 次） | 无回应 |
| `0x12` 设备信息 | 无回应 |
| `0x14` 功能配置 | 无回应 |
| `0x30` 电池 | 无回应 |
| `0x10` + `0x30` 组合 | 无回应 |
| 全零帧 | 无回应 |
| 单字节 `0xAA` | 无回应 |
| 接收器侧候选重连指令 `0xD1/0xD2/0xB4`–`0xBF` | 无回应 |

## 我们判断的原因

固件在「关灯 → 低功耗」路径上的状态机有缺陷：

1. **深度休眠门槛过低**：`deepSleepTime = 1 分钟`（开灯/关灯都一样）
2. **进入深度休眠时未正确断链**：接收器继续上报配对信息，主机误以为连接正常
3. **深度休眠下没有任何唤醒源**：连基础握手 `0x10` 都不响应，只能物理重连

驱动侧同样复现，说明不是驱动或主机协议问题。

---

## 希望你们确认/修复

1. `deepSleepTime = 1 分钟` 是否是设计值？关灯后是否应当采用更长的休眠门槛？
2. 深度休眠时，接收器的 `0xD0` 状态帧是否应上报「已断链」，而不是继续报 `state=05`？
3. 深度休眠是否应保留至少一个唤醒源（例如响应 `0x10` 握手、或响应接收器发起重连）？
4. 是否存在**比 2026-10-24 版本更新**的固件？我们刷的这两个版本未修复该问题。

---

## 复现方法（供你们验证）

1. 键盘切到 2.4G 模式并配对
2. **关闭全部灯光**
3. 停止操作约 1 分钟
4. 观察：按键无反应；此时用驱动连接会看到设备「已连接」但读不到任何配置
5. 切到蓝牙再切回 2.4G 可恢复
